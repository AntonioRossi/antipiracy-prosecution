## 1. Purpose and design note

<a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-para-00006"></a>
This document exists so that an auditor can verify that the machine translations and English-family copies currently stored for the foreign IDS references are (a) what they claim to be, (b) coherently declared in the governing registries, and (c) reproducible from primary sources. It states only current operative evidence and owners; it retains no revision history, in accordance with the repository live-status-only discipline in [`AGENTS.md`](../../../AGENTS.md). The canonical records of current state are the per-package `source-manifest.json` files and `structured_source/registry/content.json`; this memo derives from and cross-references them and does not establish a second source of truth.

<a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-para-00007"></a>
The relevant public-rule context is 37 CFR 1.98(a) and MPEP § 609.04(a). The USPTO does not require an IDS translation to be certified or verified ("There is no requirement for the translation to be verified, including reliable machine translations"). That facility does not displace the applicant's own reliability obligations: completeness, readability, and correct association of the handling text with the cited original remain relevant to the reviewing examiner, and acceptance of an IDS as a whole turns on compliance with 37 CFR 1.97, 1.98, and 1.33. Nothing here asserts that a machine translation is authoritative; the artifacts carry that limitation, and translation quality or equivalence remains subject to counsel's determination.

## 5. Independent auditor verification procedure

1. <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-orderedlist-00103"></a> <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-list-item-00104"></a> <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-plain-00105"></a> **Byte identity.** Recompute the RAW SHA-256 of each artifact in § 2 with `shasum -a 256 <path>` (or equivalent) and confirm the value matches the listed digest, the digest in the package `source-manifest.json` entry, and the `size`.
2. <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-list-item-00106"></a> <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-plain-00107"></a> **Registration coherence.** Confirm each artifact path appears in `structured_source/registry/content.json` `files` with the `fileId` above and role `convenience-derivative`, and that its `fileId` is listed in the `convenienceFiles` array of the matching package (`us-prior-art-b1`, `us-prior-art-b5`, `us-prior-art-b6`, `us-prior-art-b10`).
3. <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-list-item-00108"></a> <a id="ssp-aa11393us-ids-english-handling-acquisition-and-verification-memo-plain-00109"></a> **Aggregate gate.** Run, from the repository root: `uv --no-cache --offline run --locked --no-sync python -m navigator validate-current` and confirm `status: "passed"`. A pass is ephemeral technical status; it does not verify translation content.
