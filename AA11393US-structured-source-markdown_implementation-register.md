## Operative lessons learned

- Snapshot-scoped verification receives both the immutable byte source and its exact repository
  path inventory. Controlled-file, approval-record, forbidden-path, environment-input, and
  fresh-process render checks consume that same snapshot.
- Each verification family remains independently runnable under its declared import closure.
  Navigator snapshot and environment bracketing does not import structured-source implementation
  modules from acceptance subprocesses that intentionally expose only navigator modules.
- Every PDF-derived document owns exactly one registered source manifest. The package registry and
  human source-evidence binding include that manifest explicitly.
- Generated Markdown consumers remove only the closed `ssp-*` anchor form, interpret GFM
  backslash-escaped punctuation as visible text, and exclude generated review schedules through
  the active segmentation profile. Consumer normalization must preserve the baseline semantic
  block, claim, relation, and target identities exactly.
- Coverage verification indexes the parsed Markdown anchor set and line count once per package;
  it does not rescan a complete projection for each coverage field.
- Command capabilities, callback ownership, registered test modules, environment inputs,
  transitive verifier controls, manifests, authority data, inventories, and approval envelopes are
  closed exact values with canonical bytes.
- Identified-human review is an independent authorization boundary. Tool output, screenshots,
  comparison classifications, and model analysis are evidence aids and cannot create approval.
- Exact-side review evidence is finalized only after the identified-human authority registry is
  populated, because that registry is itself a digest-bound approval control. The review bundle
  exposes every package's complete prospective approval binding, not only its Markdown projection.
  Its path and digest remain external handoff evidence rather than content of a bound control,
  avoiding a self-referential evidence digest.
- Relation approval bindings treat endpoint identities as a canonical set. Reuse of the same
  endpoint by multiple relation assertions is represented once in `endpointBindings`, while the
  reviewed relation census continues to bind every individual assertion.
- One-way cutover is manifest-scoped. It installs the exact approved proposal, removes only
  byte-verified superseded baseline paths and closed migration-owned cache residue, and preserves
  unrelated ignored workspace content. An ignored file inside a closed controlled-plane inventory
  is still a gate input and must satisfy that plane's classification rules.
- The dynamic implementation register remains a controlled repository and global snapshot receipt
  input, but is neither a package approval side nor a structured-handoff export member. Updating a
  resolved gate therefore cannot invalidate the exact package approvals or approved export whose
  status the register reports.
- Cutover order is fixed: freeze the exact proposal and its navigator closure, generate exact
  review evidence, obtain identified-human projection approvals and later origin-appropriate
  approvals, publish the approved export, atomically install the proposal, remove migration
  residue, and run the repository-global final gate.
